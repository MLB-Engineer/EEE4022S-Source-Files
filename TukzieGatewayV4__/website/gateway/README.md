# Gateway integration for the revised developer controls

The original archive includes the website only. Your existing Raspberry Pi/vehicle subscriber must implement the new command names and return a matching ID. Keep its existing MQTT connection, credentials and hardware drivers.

## Command contract

Topic: `MQTT_COMMANDS_TOPIC`, default `tukzie/commands`. Commands are JSON, QoS 1, not retained.

| Button | `cmd` value | Required action |
| --- | --- | --- |
| Hoot | `hoot` | Sound the existing hooter |
| Left Indicator on/off | `left_indicator_on` / `left_indicator_off` | Set an explicit state; do not blindly toggle |
| Right Indicator on/off | `right_indicator_on` / `right_indicator_off` | Set an explicit state |
| Hazards on/off | `hazards_on` / `hazards_off` | Set an explicit state |
| Send message | `message` | Process/display/log the separate `message` string (1–280 characters) |

Example envelope (IDs, time and signatures are generated by the website):

```json
{
  "cmd": "left_indicator_on",
  "target": "vehicle",
  "timestamp": 1791363600.123,
  "command_id": "b7c214ad-1baf-4fb4-b26d-e819388b7061",
  "schema_version": "0.2.0",
  "auth_token": "legacy-signature",
  "auth_token_v2": "full-envelope-signature"
}
```

The legacy signature remains `HMAC-SHA256(secret, "cmd:target:timestamp")` for older operator integrations. For the new developer commands, verify **`auth_token_v2`** using `command_protocol.sign_envelope`. It covers `cmd`, `target`, `timestamp`, `command_id` and `message` when present, serialized as sorted compact JSON. Do not validate only the legacy signature for free-text messages: it does not cover their contents.

## Use the included adapter

Copy `command_protocol.py` and `gateway/command_handler.py` onto the Pi so both can be imported by the existing subscriber. Create **one** `CommandHandler` when your subscriber starts; reuse it for every command so duplicate detection works.

```python
import os
from command_handler import CommandHandler, mqtt_callback

# apply_vehicle_command is your existing hardware integration function:
#   apply_vehicle_command(cmd: str, message: str | None) -> str | None
# It must apply the requested action before returning and raise if it fails.
handler = CommandHandler(
    secret=os.environ["COMMAND_SHARED_SECRET"],
    execute=apply_vehicle_command,
)

# Inside the subscriber's existing on_message callback:
if msg.topic == os.getenv("MQTT_COMMANDS_TOPIC", "tukzie/commands"):
    mqtt_callback(
        handler, client, msg,
        ack_topic=os.getenv("MQTT_ACKS_TOPIC", "tukzie/acks"),
    )
    return
```

`apply_vehicle_command` is the explicit hardware integration point; no GPIO pins or vehicle CAN commands have been guessed. For `_on` and `_off`, call the device's explicit set-state functions. If hazards and individual indicators are mutually exclusive on your rig, enforce that in the hardware handler and return a descriptive note. For `message`, log/display the received text as appropriate. Never execute the message as Python or a shell command.

The adapter validates signatures and command age (ten seconds), rejects retained commands, deduplicates redelivery, and sends `ack` only after the supplied callback returns successfully. It returns `rejected` when that callback raises. Synchronize the gateway and server clocks. Its deduplication cache is in memory: a gateway restart loses it. Keep command expiry and your existing device-side rate limits/interlocks.

## Acknowledgement contract

Publish to `MQTT_ACKS_TOPIC`, default `tukzie/acks`, with `retain=false`:

```json
{
  "command_id": "b7c214ad-1baf-4fb4-b26d-e819388b7061",
  "cmd": "left_indicator_on",
  "status": "ack",
  "note": "Left indicator on"
}
```

Echo the **same `command_id` and `cmd`**. Other accepted terminal statuses are `rejected`, `error`, and `failed`. The website records send time, acknowledgement reception time and elapsed milliseconds itself. An unmatched ID, wrong command, expired acknowledgement or retained acknowledgement cannot mark the current command successful.

A legacy gateway that publishes only `{"cmd":"hoot","status":"ack"}` will not confirm a new Developer request; add the ID. The old Operator UI retains legacy acknowledgement support for its original commands.

No acknowledgement within ten seconds means **unconfirmed outcome**, not proof that the physical action failed. The website provides an explicit off command if an indicator/hazard acknowledgement is lost.
